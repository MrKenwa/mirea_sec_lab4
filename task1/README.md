# Задание 1. Перебор паролей формы DVWA

Учебный переборщик на Go для локальной DVWA. Адрес фиксирован:
`http://127.0.0.1:4280/vulnerabilities/brute/`, логин — `admin`.
Реализован полный перебор комбинаций, не словарь. Только задание 1.

## Подготовка и запуск

1. Запусти DVWA через Docker на порту 4280.
2. Войди в браузере в DVWA (`admin` / `password` после стандартного сброса).
3. Экспортируй cookie для `127.0.0.1` в формате Netscape в `/Users/maxim/study/beza/pr4/task1/cookies.txt`.
   Абсолютный путь зафиксирован в константе `cookiesPath` в `main.go`.
   Используй настоящий текстовый файл с табуляцией, без обратных слешей из оформления сообщения.
   В программе используется `PHPSESSID`; cookie `security=low` отправляется явно независимо от значения в файле.
   Пароль входа в оболочку DVWA и проверяемый пароль формы — разные этапы работы.
4. Из каталога `/Users/maxim/study/beza/pr4/task1`:

```sh
go build -o dvwabrute .
./dvwabrute -charset digits -min-length 1 -max-length 2
```

Это проверит 110 числовых комбинаций (10 + 100). Стандартный пароль `password`
в этот диапазон не входит, поэтому для неизменённого admin ожидается `exhausted`.

Флаги:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-charset` | `digits` | `digits`, `lower`, `alnum`, `printable` |
| `-min-length` | `1` | Нижняя граница длины |
| `-max-length` | `4` | Верхняя граница длины |

Алфавиты сохранены из pr3: digits — цифры; lower — строчные латинские буквы;
alnum — строчные, прописные латинские буквы и цифры; printable — ASCII 32–126.
Комбинации не хранятся целиком в памяти. Параметры длины: 1–64, пространство поиска должно помещаться в uint64.

Количество параллельных работников задано константой `const workers = 6` в `main.go`. Каждый работник отправляет
GET-запрос с `username=admin`, очередным `password` и `Login=Login`.
`user_token` для Low не требуется. Движок останавливается после явного сообщения об успехе;
текущие HTTP-запросы отменяются. Порядок проверки при параллельной работе не фиксирован.
Выводятся статус, число завершённых проверок, время и скорость; при успехе — пароль.
Статусы: `found`, `exhausted`, `cancelled`, `error`. Ctrl+C останавливает программу.
Код выхода: 0 — найден пароль или диапазон исчерпан; 2 — ошибка; 130 — отмена перебора.
Тайм-аут одного HTTP-запроса — 10 секунд. Ошибки сети, HTTP и редиректы останавливают перебор,
а не считаются неправильными паролями. Автоматического входа и повторных запросов нет.

## Как показать успешный полный перебор

Для быстрого опыта нужен короткий пароль учебной учётной записи admin, например `12`.
Установи его через Change Password внутри DVWA (это изменяет учебную запись),
при необходимости снова войди и экспортируй свежие cookie. Затем:

```sh
./dvwabrute -charset digits -min-length 2 -max-length 2
```

Ожидается `found` и `Пароль: 12`. Сам скрипт пароли и базу данных не изменяет.
Проверять стандартный `password` полным перебором практически неудобно:
только для восьми строчных букв существует 26^8 = 208827064576 комбинаций.

## Файлы и связь с pr3

- `cursor.go` — генератор `Jobs`/`Cursor`, перенесён из pr3 с заменой имени пакета.
- `config.go` — алфавиты, границы и расчёт числа комбинаций из pr3; убраны настройки прогресса.
- `search.go` — параллельный движок по образцу pr3; проверка через HTTP, учёт каждой попытки, ошибки и отмена.
- `dvwa.go` — чтение cookie, проверка доступа к форме, GET-запросы и распознавание ответа.
- `main.go` — аргументы, запуск и вывод результата.
- `dvwa_test.go` — проверки HTTP-протокола, ошибок, поиска и отмены на локальном тестовом сервере.

Зависимости — только стандартная библиотека Go, исходный pr3 не изменён.

```sh
go test -race ./...
go vet ./...
```

Если DVWA перенаправляет на вход, заново войди в браузере и замени `cookies.txt`.
Файл с сессией исключён из Git. PHP может сериализовать обработку запросов с одной сессией:
параллельные работники на клиенте не гарантируют ускорения на сервере.

## Диагностика ошибок

Ошибка выводится в stderr с датой и временем. Для HTTP-ответов показываются URL
с проверяемым паролем, статус, время запроса, Content-Type, размер полученного тела,
объявленный Content-Length, Location и Retry-After (если они есть), а также первые
1500 символов ответа без лишних пробелов. `Content-Length: -1` означает, что длина
не объявлена сервером. Для сетевых сбоев показывается исходная ошибка транспорта.

В `/Users/maxim/study/beza/pr4/task1/dvwabrute-error.log` добавляется та же диагностика
и полное полученное тело ответа (до 2 МиБ; превышение лимита отмечается явно).
По нему можно увидеть ошибку PHP/БД даже при HTTP 200. Cookie и Set-Cookie
в диагностику не выводятся. Журнал содержит проверяемые пароли и ответы локальной DVWA;
он исключён из Git. Чтобы начать журнал заново, удали этот файл перед запуском.

### Причина остановки примерно после 14 тысяч попыток

При проверке воспроизведён ответ HTTP 200 с ошибкой PHP:
`PDOException: SQLSTATE[HY000] [2002] Cannot assign requested address`.
В контейнере DVWA диапазон временных портов — 32768–60999 (28232 порта);
обнаружено 28231 соединение к MariaDB в состоянии TIME_WAIT.
`dvwaDatabaseConnect()` открывает два соединения с БД на каждый запрос (mysqli и PDO),
поэтому при быстром переборе свободные порты заканчиваются примерно за 14 тысяч попыток.
Это ограничение соединений DVWA с БД, а не признак неправильного пароля.
Новая диагностика показывает ошибку PHP и сохраняет исходный ответ; настройки контейнеров
и алгоритм остановки при ошибке не изменены.

## Ограничение скорости

В `main.go` задано `const requestsPerSecond = 100`. Один общий `time.Ticker`
выдаёт разрешение на запрос каждые 10 мс. Все 6 работников ожидают один канал:
каждый тик получает только один из них, поэтому 100 — суммарный лимит, а не лимит
на каждого работника. После начальной проверки сессии запускается таймер; перед каждым запросом
перебора `dvwa.get` ждёт разрешение или отмену контекста. Ожидание не мешает Ctrl+C.
Тики не накапливаются в очередь для последующего массового запуска.
Фактическая скорость может быть ниже из-за задержек сервера и планирования Go.
Число завершённых проверок, делённое на время перебора, — измеренная средняя
скорость в итоговой статистике; это отдельная величина от заданного лимита.
